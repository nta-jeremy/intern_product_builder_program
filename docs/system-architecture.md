# System Architecture

> **Scope:** YODY Intern Product Builder Portal — Next.js 16 App Router, React 19, single-PortalContext state model, dual-CSS system.
> **Audience:** engineers adding routes, extending overlays, debugging theme/state issues.
> **Last updated:** 2026-07-20

---

## 1. Architecture Overview

### 1.1 Mental model
Portal là một **single-page application về mặt UX** (header + content + 3 overlays), nhưng chia thành nhiều route trong Next.js App Router. Mọi state dùng chung sống trong **một** `PortalContext` ở root của route group `(portal)`.

## 2. State Management

### 2.1 Why one context (vs Redux/Zustand)
Portal chỉ có **5 state slots**:
- 1 theme slot (delegate tới `useTheme`)
- 3 overlay slots (comp / badge / quiz)
- 1 bridge slot (`roadmapQuizLesson` — roadmap click → quiz open)

Một `useState` per slot trong `PortalProvider` đủ. Memo hóa `value` qua `useMemo` để re-render tối thiểu.

### 2.2 `PortalContext` shape
```ts
interface PortalContextValue {
  // Theme (delegated)
  theme: "light" | "dark";
  isDark: boolean;
  toggleTheme: () => void;

  // Competency Drawer
  comp: string | null;          // NL code
  openComp: (code: string) => void;
  closeComp: () => void;

  // Badge Modal
  badgeIdx: number | null;     // index in BADGES[]
  openBadge: (i: number) => void;
  closeBadge: () => void;

  // Quiz Modal
  quizLessonId: string | null; // "I1.1" | "I1.2" | ...
  openQuiz: (id?: string) => void;  // default: "I1.1"
  closeQuiz: () => void;

  // Roadmap → Quiz bridge
  roadmapQuizLesson: string | null;
  setRoadmapQuizLesson: (id: string) => void;
}
```

### 2.3 State flow examples

**Open competency drawer (from `Competencies.tsx`):**
```
User clicks NL card
   │
   ▼
openComp("NL3")
   │
   ▼
PortalProvider.setComp("NL3")
   │
   ▼
Overlays.tsx receives compCode="NL3" prop
   │
   ▼
Renders <CompetencyDrawer code="NL3" />
```

**Open quiz from roadmap:**
```
User clicks "Làm quiz" trên roadmap card
   │
   ▼
setRoadmapQuizLesson("I2.3")  → context updates
   │
   ▼
useEffect in caller: openQuiz(roadmapQuizLesson)
   │
   ▼
PortalProvider.setQuizLessonId("I2.3")
   │
   ▼
Overlays.tsx renders <QuizModal lessonId="I2.3" />
   │ reads LESSONS from lib/data
   ▼
Quiz 2-phase state machine: intro (TL;DR) → questions
```

### 2.4 Persistence (localStorage)
| State | Persisted? | Key |
|-------|-----------|-----|
| `theme` | ✅ | `yds-ui-theme` |
| `comp` (open drawer) | ❌ | — |
| `badgeIdx` (open modal) | ❌ | — |
| `quizLessonId` (open quiz) | ❌ | — |
| Quiz answers | ❌ | — |
| `roadmapQuizLesson` | ❌ | — |

> Persisting modal/quiz state là **planned** cho [Project Roadmap M2](./project-roadmap.md#milestone-2-q4-2026--quiz-system-with-persistence--badge-unlock-animations).

## 3. Theme Subsystem

### 3.1 Two CSS systems side-by-side

| System | Selector | File | Consumer |
|--------|----------|------|----------|
| **YODY DS v3** (primary) | `[data-theme="light"]` / `[data-theme="dark"]` | `styles/globals.css` (1,376 lines) | Mọi section, Header, Overlays |
| **shadcn radix-nova** | `.dark` (class) | `app/globals.css` (145 lines) | `components/ui/button.tsx` only |

> ⚠️ **Incompatibility:** shadcn key trên `.dark` class — YODY key trên `[data-theme]` attribute. `Button` có thể **không respect dark mode**. Xem [Roadmap §5](./project-roadmap.md#5-known-technical-debt).

### 3.2 Theme flow (light/dark)

```
┌────────────────────────────────────────────────────────────┐
│  Browser load (before React)                                │
│                                                              │
│  Inline script (app/layout.tsx:63)                          │
│    localStorage.getItem('yds-ui-theme')                      │
│      → 'light' | 'dark' | null                              │
│    document.documentElement.dataset.theme = …               │
│    document.documentElement.dataset.surface = 'portal'      │
└────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌────────────────────────────────────────────────────────────┐
│  React hydrates                                              │
│                                                              │
│  useTheme() reads localStorage → setState                   │
│    useEffect → dataset.theme = theme (no-op if same)        │
│                                                              │
│  PortalShell (app/(portal)/layout.tsx) renders              │
│    <div data-theme={theme}> ...                              │
└────────────────────────────────────────────────────────────┘
                              │
                              │  user clicks theme toggle
                              ▼
┌────────────────────────────────────────────────────────────┐
│  Header → usePortal().toggleTheme()                          │
│    ↓                                                         │
│  useTheme().toggle() → setTheme('dark' | 'light')            │
│    ↓                                                         │
│  useEffect → dataset.theme updates + localStorage write      │
│    ↓                                                         │
│  CSS variables in styles/globals.css re-resolve             │
│    via [data-theme="dark"] { --bg: #0e0f24; --fg-1: #…; }   │
└────────────────────────────────────────────────────────────┘
```

### 3.3 Dark token override
Vị trí: `styles/globals.css:1271–1286` (selector `[data-theme="dark"] { ... }`).
Ví dụ tokens bị override:
- `--bg: #fcfcff` → `#0e0f24`
- `--fg-1: #1a1b3a` → `#e6e8f5`
- `--card: #ffffff` → `#1a1b3a`
- `--border-light: #ecedf8` → `#2a2b4a`
- `--shadow-*` — giữ nguyên (iris-tinted) vì shadow tone đã cool enough.

### 3.4 Surface adapter
`<body data-surface="portal">` (set trong `app/layout.tsx:103`) + `document.documentElement.dataset.surface='portal'` (set trong inline script).
4 surface hiện có trong YODY DS: `portal` (active), `marketing`, `app`, `store`. Portal chỉ dùng `portal`.

### 3.5 FOUC prevention
- Inline script trong `<head>` (trước khi `<body>` parse).
- `suppressHydrationWarning` trên `<html>` và `<body>` vì React sẽ so sánh DOM và thấy attribute đã set.
- Không có flash vì theme resolve trước khi paint.

## 4. Overlay System

### 4.1 Single component, 3 slots

`components/Overlays.tsx` (1028 lines) là **một** component render 3 overlays dựa trên props truyền từ `PortalShell`:

```tsx
<Overlays
  compCode={comp}            // Competency Drawer
  onCloseDrawer={closeComp}
  badgeIdx={badgeIdx}        // Badge Modal
  onCloseBadge={closeBadge}
  quizLessonId={quizLessonId}// Quiz Modal
  onCloseQuiz={closeQuiz}
/>
```

Mỗi overlay chỉ mount khi prop tương ứng non-null (return `null` nếu không).

### 4.2 Z-index stack

| Overlay | z-index | Width | Animation | Notes |
|---------|---------|-------|-----------|-------|
| Header | 60 | full | sticky top | `position: sticky` |
| Competency Drawer | 80 | 500px | slide-in right (`dcDrawer`) | L1–L5 ladder, highlight L2 gold |
| Badge Modal | 80 | 460px | pop center (`dcPop`) | gradient top bar + tone-tinted icon |
| Quiz Modal | 90 | 600px | pop center (`dcPop`) | 2-phase state machine |
| Modal backdrop (overlay) | 81 (drawer) / 80 (badge) | full | `dcOverlay` (fade) | semi-transparent navy |

> Quiz cao hơn drawer/badge vì nó có thể mở chồng (mở quiz từ lesson detail đã có drawer).

### 4.3 Quiz Modal state machine

```
┌──────────────┐  click "Bắt đầu"   ┌──────────────────┐
│  INTRO phase │ ─────────────────► │  QUIZ phase      │
│  - TL;DR     │                    │  - questions[]   │
│  - "Bắt đầu" │                    │  - answer record │
│  button      │                    │  - submit button │
└──────────────┘                    └────────┬─────────┘
                                            │ click "Nộp bài"
                                            ▼
                                     ┌──────────────────┐
                                     │  RESULT phase    │
                                     │  - correct >= 2  │
                                     │    → PASS        │
                                     │  - else RETRY    │
                                     └──────────────────┘
```

Pass = `correctAnswers >= 2`. Retry → reset `answers` + back to intro.

### 4.4 Trigger surface

| Action | Trigger location | Opens |
|--------|------------------|-------|
| Click NL card | `Competencies.tsx` | Competency Drawer |
| Click badge card | `Badges.tsx` | Badge Modal |
| Click "Làm quiz" trên roadmap | `RoadmapTimeline.tsx` | Quiz Modal |
| Click "Bắt đầu học" CTA | `Overview.tsx` | (route to `/learn-hub`) |
| Header logo click | `Header.tsx` | (route to `/`) |

## 5. Routing Model

### 5.1 Route group
```
app/
├── layout.tsx              ← RootLayout (Server, lang="vi", metadata)
├── globals.css             ← shadcn layer
└── (portal)/               ← Route group (no URL segment)
    ├── layout.tsx          ← PortalLayout (Client, wraps PortalProvider)
    ├── page.tsx            → /
    ├── roadmap/page.tsx    → /roadmap
    ├── competencies/page.tsx → /competencies
    ├── badges/page.tsx     → /badges
    ├── scorecard/page.tsx  → /scorecard
    ├── projects/page.tsx   → /projects
    ├── learn-hub/page.tsx  → /learn-hub
    └── learn/
        └── [lessonId]/page.tsx → /learn/:lessonId
```

### 5.2 Dispatcher pattern (lesson)
Dynamic segment `[lessonId]` được resolve bằng if-else chain trong `page.tsx`:

```tsx
"use client";
import { useParams } from "next/navigation";
import { LessonI11 } from "@/components/sections/LessonI11";
// ... 5 more imports

export default function LearnPage() {
  const { lessonId } = useParams<{ lessonId: string }>();

  if (lessonId === "I1.1") return <div className="i11-surface"><LessonI11 /></div>;
  if (lessonId === "I1.2") return <div className="i12-surface"><LessonI12 /></div>;
  // ... 4 more

  // Fallback: "Coming soon"
  return <main>…<h2>Buổi {lessonId} đang được chuẩn bị</h2>…</main>;
}
```

### 5.3 Routing rules
- ❌ **No nested layouts** trong `(portal)/<segment>/` — tất cả pages share `app/(portal)/layout.tsx`.
- ❌ **No `loading.tsx` / `error.tsx` / `not-found.tsx`** hiện tại — Next.js dùng defaults.
- ❌ **No metadata per page** — chỉ root `metadata` trong `app/layout.tsx`. SEO mặc định dùng title template `"%s | Intern Product Builder Portal"`.
- ✅ **Dynamic lessonId dispatcher** — pattern chấp nhận được vì chỉ 6-13 routes; nếu > 20 nên cân nhắc `dynamic import()` + manifest map.

## 6. Asset Pipeline (Build-time, Python)

### 6.1 Hai script, hai phase

**Phase 01 — `scripts/extract_assets.py` (one-shot, 238 lines)**
- Input: `public/demo/Intern Product Builder Portal (standalone).html` (DC bundle)
- Output:
  - `public/fonts/*` — WOFF2/TTF files
  - `styles/globals.raw.css` — extracted CSS
  - `lib/data.ts` (raw) — initial seed
  - asset map JSON
- Chạy **một lần** khi port từ DC bundle mới. Không idempotent — ghi đè.

**Phase 03 — `scripts/build_globals.py` (idempotent, 102 lines)**
- Input: `styles/globals.raw.css`
- Output: `styles/globals.css` (production-ready, 1376 lines)
- Chạy **mỗi khi** `globals.raw.css` thay đổi. Có thể chạy lại nhiều lần — output ổn định.

### 6.2 Pipeline isolation
- Scripts **không** được Next.js build gọi — chạy thủ công (hoặc pre-commit hook nếu team thêm).
- `styles/globals.css` (production) **luôn được commit** vì Vercel cần file này để build.
- `public/demo/` (DC bundle) là **legacy archive** — không load runtime, có thể xóa trong tương lai (xem [Roadmap §6 Open Questions](./project-roadmap.md#6-open-questions)).

### 6.3 Thứ tự khi thay đổi CSS tokens
1. Sửa `styles/globals.css` trực tiếp (nếu chỉnh production)
2. Hoặc: sửa `styles/globals.raw.css` → chạy `python scripts/build_globals.py` → commit output
3. Verify: `npm run build` locally, check không có token missing

## 7. Lesson Surface Pattern (chi tiết)

Mỗi lesson page có class `.i11-surface`, `.i12-surface`, … scoped trong `styles/globals.css` cuối file. Pattern:

```css
.i11-surface { background: var(--bg-warm); }
.i11-surface ::selection { background: var(--iris); color: #fff; }
.i11-surface a { color: var(--iris-deep); }
.i11-surface a:hover { color: var(--iris); }
.i11-surface .kh-part { transition: transform .14s, box-shadow .14s; }
.i11-surface .kh-part:hover { transform: translateY(-2px); box-shadow: var(--shadow-lg); }
.i11-surface .kh-toc:hover { background: #fff; }
.i11-surface .kh-opt { transition: background .12s, border-color .12s; }
.i11-surface .kh-nav:hover { opacity: .62; }

/* responsive overrides */
@media (max-width: 720px) {
  .i11-surface .i11-overview-grid { grid-template-columns: 1fr !important; }
  .i11-surface .i11-read-layout { flex-direction: column !important; }
  .i11-surface .i11-read-toc { width: 100% !important; position: static !important; … }
}
```

> Convention: prefix `.kh-` = "knowledge hub" (tên dùng trong HTML gốc). Khi port lesson mới, copy pattern từ lesson đã có, đổi prefix `.i<XY>-`.
